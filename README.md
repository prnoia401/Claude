# Quest Remote

Android-приложение для управления VR-шлемами с телефона по кабелю **Type‑C ↔ Type‑C**
(телефон работает как USB-хост) или по Wi‑Fi. Внутри своя реализация протокола ADB,
поэтому ни root, ни бинарник `adb` на телефоне не нужны.

**Телефон:** Android 10 и новее (технически работает с Android 8.0, minSdk 26), включая Android 15 с edge-to-edge.
Для подключения по кабелю телефон должен поддерживать USB-хост (OTG). Без этого остаётся Wi‑Fi.

**Шлемы:**

| Устройство | Подключение | Настройки |
|---|---|---|
| Meta Quest 2 / 3 / 3S / Pro | USB, Wi‑Fi | частота под модель, CPU/GPU, фовеация, eye-buffer от родного разрешения, Guardian, датчик присутствия |
| PICO Neo 3 / 4 / 4 Ultra | USB, Wi‑Fi | общие настройки Android (у PICO нет документированных аналогов `debug.oculus.*`) |
| Любое Android-устройство с отладкой | USB, Wi‑Fi | общие настройки Android |

Модель определяется автоматически по `ro.product.*` (кодовые имена Quest: hollywood, eureka, panther, seacliff).

## Возможности

| Вкладка | Что умеет |
|---|---|
| **Шлем** | подключение по USB/Wi‑Fi, поиск в сети, автопереподключение, состояние (модель, прошивка, батарея, зарядка, температура, IP, память), **живой экран** (обновляемые скриншоты), скриншот, **запись видео** (`screenrecord`, до 3 мин), **ввод текста** в шлем, **открыть ссылку** в браузере шлема, кнопки Домой/Назад/громкость/сон, перезагрузка, выключение, «Включить ADB по Wi‑Fi» |
| **Пульт** | команды нашему клиенту на шлеме: запустить видео из памяти шлема или по ссылке, ▶/⏸, ±10 с, перемотка ползунком, стоп, повтор, громкость, запуск любого приложения, сообщение в шлем, произвольные JSON-команды. Связь через ADB-туннель или напрямую по Wi‑Fi с PIN |
| **Приложения** | список пакетов, установка APK с прогрессом, запуск (Quest VR, PICO, 2D), остановка, логи приложения, **скачать APK со шлема**, сведения о версии, очистка данных, удаление |
| **Файлы** | файловый менеджер шлема (протокол `adb sync`): папки, закладки (Download, Movies, OBB, Android/data), скачать на телефон, загрузить с телефона, установить APK из памяти шлема, новая папка, удаление |
| **Настройки** (кнопка на вкладке «Шлем») | набор под конкретную модель (см. таблицу выше), «не засыпать на зарядке», отключение анимаций, сброс |
| **Консоль** | живой logcat, пресеты (ошибки, Unity, Unreal, FPS VrApi, падения), фильтр по тексту, подсветка уровней, экспорт, произвольные `adb shell` команды, журнал подключений с временем |

Меню (⋮): автопереподключение, «не гасить экран телефона», сведения о телефоне.

## 1. Установка приложения на телефон

APK собирает GitHub Actions при каждом пуше. Готовые файлы лежат в **Releases** репозитория
(`build-N`), а также в артефактах запуска workflow **Android APK**.

Телефон подключён к компьютеру по ADB:

```bash
adb install -r QuestRemote-N.apk
adb shell am start -n com.prnoia.questremote/.ui.MainActivity
```

Другой вариант: скачать APK прямо на телефон со страницы Releases и открыть его
(понадобится разрешить установку из этого источника).

Все сборки подписаны одним тестовым ключом (`keystore/debug.keystore`), поэтому
новая версия ставится поверх старой без удаления. **Для продакшена этот ключ не годится.**

Собрать локально (нужен Android SDK / Android Studio):

```bash
./gradlew assembleDebug          # APK: app/build/outputs/apk/debug/app-debug.apk
./gradlew installDebug           # сразу на подключённый телефон
./gradlew testDebugUnitTest      # тесты протокола ADB против поддельного adbd
```

## 2. Отладка самого приложения на телефоне

Разъём Type‑C у телефона будет занят шлемом, поэтому отладку телефона переносим на Wi‑Fi,
**пока телефон ещё подключён к ПК кабелем**:

```bash
adb tcpip 5555                       # телефон начинает слушать ADB по сети
adb connect <IP_телефона>:5555       # IP: Настройки → О телефоне → Статус
# теперь кабель от ПК можно отключить и воткнуть шлем
adb -s <IP_телефона>:5555 logcat --pid=$(adb -s <IP_телефона>:5555 shell pidof -s com.prnoia.questremote)
```

На Android 11+ можно без кабеля: *Для разработчиков → Отладка по Wi‑Fi → Подключить с кодом*,
затем `adb pair <ip>:<port>` и `adb connect <ip>:<port>`.

Всё, что приложение делает со шлемом, дублируется во вкладке **Консоль**.
Её можно выгрузить кнопкой **Экспорт**.

## 3. Подготовка шлема (один раз)

**Meta Quest 2 / 3 / 3S / Pro:** в приложении **Meta Horizon** на телефоне:
*Устройства → Настройки гарнитуры → Режим разработчика → Вкл*
(нужна бесплатная учётная запись разработчика Meta). Затем перезагрузите шлем.

**PICO Neo 3 / 4 / 4 Ultra:** *Настройки → Общие → О устройстве* → 7 раз нажать на номер сборки
(или версию ПО), затем *Настройки → Разработчик → Отладка по USB → Вкл*.

## 4. Подключение по кабелю Type‑C ↔ Type‑C

1. Воткните кабель в телефон и в шлем. Кабель должен передавать данные, а не только заряжать.
2. Android предложит открыть **Quest Remote** для этого устройства. Можно поставить «Всегда».
   Если окно не появилось, откройте приложение и нажмите **Подключить по USB**.
3. Наденьте шлем и в диалоге **«Разрешить отладку по USB?»** нажмите *Разрешить*.
   Лучше с галочкой «Всегда разрешать», тогда при следующих подключениях вопроса не будет.

**Если шлем не находится.** У кабеля C‑C роли хост/устройство согласуются автоматически,
и иногда хостом становится шлем. Что можно сделать:

- в шторке телефона нажмите на уведомление USB → **«USB управляет: это устройство»**;
- переподключите кабель другим концом (или переверните штекер);
- используйте OTG-переходник на стороне телефона. Он принудительно делает телефон хостом.

## 5. Переход на Wi‑Fi

Подключившись по кабелю, нажмите **«Включить ADB по Wi‑Fi»**. Приложение само подставит IP шлема.
Через пару секунд нажмите **«По Wi‑Fi»**, и кабель можно отключить.
Режим сбрасывается после перезагрузки шлема. Без кабеля его можно включить с ПК: `adb tcpip 5555`.

## Автоматизация: ничего не нажимать

| Событие | Что делает приложение |
|---|---|
| Запуск приложения | подключается к шлему по кабелю, если он воткнут, иначе по Wi‑Fi (по сохранённому IP) |
| Воткнули кабель | подключается по USB; если шлем не ответил с первого раза — до 3 повторов |
| Подключились по USB | шлем подключается к рабочей сети Wi‑Fi (Android 11+: Quest 2/3/3S, PICO 4 Ultra) и включает ADB по сети, его IP запоминается |
| Выдернули кабель | переключается на Wi‑Fi без ввода адреса |
| Воткнули кабель снова | возвращается на USB |
| Подключились к шлему | вкладка «Пульт» сама ставит/обновляет клиент на шлеме, выдаёт ему разрешения, запускает и подключается |

Сеть по умолчанию — **ВАЙФАЙДЛЯКРУТЫХ**, её название и пароль можно поменять в карточке «Автоматизация»
на вкладке «Шлем». Там же кнопки «Шлем → Wi‑Fi», «Отключить Wi‑Fi шлема» и «Подключить телефон к этой сети»:
на Android 11+ это системный диалог сохранения сети, после него телефон подключается к ней сам.

На шлемах с Android 10 (PICO Neo 3, PICO 4 на старой прошивке) Android не даёт подключить Wi‑Fi из ADB —
подключите шлем к сети один раз вручную, дальше он подключается сам, а ADB по сети приложение включит.

Автопереподключение выключается в меню ⋮ → «Автопереподключение».

## Проверка качества

Каждый пуш прогоняет в GitHub Actions:

- unit-тесты протокола ADB, sync, разбора громкости и определения моделей;
- Android Lint (совместимость API с Android 8+);
- **сквозные тесты на эмуляторе Android 11**: подключение к настоящему adbd, shell, громкость
  (значение перечитывается из системы), файлы, скриншот, logcat, установка клиента, видео
  (запуск, пауза, перемотка, громкость, стоп), запуск приложений и нажатия кнопок в интерфейсе.

## Пульт и клиент на шлеме

На шлем ставится второе приложение — **Quest Remote Client** (модуль `client/`). Оно:

- держит фоновый сервер команд на порту **47800** и поднимается само после включения шлема;
- воспроизводит видео во встроенном полноэкранном плеере;
- запускает другие приложения и передаёт им параметры;
- показывает на своём экране IP, PIN и журнал полученных команд.

**Установка:** вкладка «Пульт» → «Установить клиент на шлем». Клиент вшит в APK пульта.
Кнопка ставит его по ADB, выдаёт разрешения на показ поверх окон и чтение видео, затем запускает.

**Два способа связи (протокол один):**

| Способ | Что нужно | Когда удобно |
|---|---|---|
| Через ADB | подключение на вкладке «Шлем» (USB или Wi‑Fi ADB) | отладка, режим разработчика уже включён |
| По Wi‑Fi | IP шлема и PIN с экрана клиента; кнопка «Найти» ищет клиентов в сети | эксплуатация: режим разработчика и кабель не нужны |

### Протокол

TCP, одна JSON-строка на сообщение. Запрос `{"id":1,"cmd":"…", …}` → ответ `{"id":1,"ok":true, …}`
или `{"id":1,"ok":false,"error":"…"}`. Клиент сам рассылает события `{"event":"status", …}`
при изменении состояния плеера (позиция обновляется раз в секунду).
По Wi‑Fi первой командой нужно отправить `{"cmd":"hello","pin":"1234"}`.
Подключения через ADB-туннель (с localhost) доверенные.

| Команда | Параметры | Что делает |
|---|---|---|
| `ping` | — | версия клиента, модель, Android |
| `status` | — | `state` (idle/loading/playing/paused/ended/error), `source`, `position`, `duration`, `volume`, `loop` |
| `play` | `path` или `url`, `loop`, `position` (мс) | открыть видео в плеере клиента |
| `pause` / `resume` / `toggle` / `stop` | — | управление воспроизведением |
| `seek` / `seek_by` | `position` / `delta` (мс) | перемотка |
| `volume` | `level` 0–100 | громкость медиа |
| `loop` | `value` true/false | повтор |
| `list_media` | `dir` (необязательно) | видео в Movies, Download, DCIM и др. |
| `list_apps` | — | приложения с иконкой запуска (в т.ч. VR) |
| `launch` | `package`, `extras` {ключ: значение} | запустить приложение и передать ему параметры |
| `broadcast` | `action`, `package`, `extras` | отправить broadcast вашему VR-приложению |
| `message` | `text` | всплывающее сообщение в шлеме |

**Управление вашим собственным VR-приложением** (Unreal/Unity) делается двумя путями:
- `launch` с `extras`: приложение при старте читает параметры из Intent (например `{"scene":"lab2"}`);
- `broadcast`: приложение регистрирует BroadcastReceiver на свой action, например `com.company.vr.COMMAND`,
  и реагирует на команды «пауза», «следующая сцена» и т. п. уже во время работы.

Без сети, только по ADB, команду можно отправить и так:

```bash
adb shell am broadcast -n com.prnoia.questclient/.CommandReceiver \
  -a com.prnoia.questclient.COMMAND --es json '{"cmd":"play","path":"/sdcard/Movies/film.mp4"}'
```

## Как это устроено

```
app/src/main/java/com/prnoia/questremote/
├── adb/
│   ├── AdbConnection.kt   протокол ADB: CNXN/AUTH/OPEN/OKAY/WRTE/CLSE, потоки, flow control
│   ├── AdbCrypto.kt       RSA-ключ телефона, подпись токена, формат публичного ключа adbd
│   ├── AdbTransport.kt    интерфейс транспорта + TCP (Wi‑Fi)
│   ├── UsbTransport.kt    USB Host API: bulk-эндпоинты ADB-интерфейса (0xFF/0x42/0x01)
│   ├── UsbAdb.kt          поиск устройств и запрос USB-разрешения
│   ├── NetworkScanner.kt  поиск открытого порта 5555 в подсети /24
│   └── QuestController.kt состояние подключения, shell, установка APK, скриншот, logcat
│   └── RemoteLink.kt      связь с клиентом: JSON поверх ADB-туннеля tcp:47800 или Wi‑Fi
└── ui/                    MainActivity и вкладки: Device, Remote, Apps, Files, Tweaks, Console

client/src/main/java/com/prnoia/questclient/   приложение для шлема
├── CommandService.kt   фоновая служба: сервер, объявление в сети (NSD), рассылка статуса
├── CommandServer.kt    TCP-сервер, PIN для сетевых подключений
├── CommandHandler.kt   выполнение команд
├── PlayerActivity.kt   полноэкранный плеер
└── Receivers.kt        команды через am broadcast, автозапуск после загрузки
```

- Установка APK: `exec:cmd package install -S <размер>` с потоковой передачей файла.
- Скриншот: `exec:screencap -p`.
- Перезагрузка и `tcpip`: служебные сервисы adbd `reboot:` и `tcpip:5555`.
- Ключ телефона хранится в приватной папке приложения. После переустановки
  с очисткой данных шлем спросит разрешение заново.

## Ограничения и идеи на потом

- «Живой экран» — это обновляемые скриншоты (1–3 кадра/с), а не видеопоток как в scrcpy.
- `screenrecord` на некоторых прошивках Quest/PICO записывает только 2D-слой или отказывается работать.
- Ввод текста (`input text`) поддерживает только ASCII: кириллицу так не набрать.
- Параметры `debug.oculus.*` действуют до перезагрузки и применяются при следующем запуске VR-приложения.
- Уровень заряда контроллеров не показывается: у Meta нет стабильного публичного способа его получить.
