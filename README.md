# Quest Remote

Тестовое Android-приложение для управления шлемом **Meta Quest 2** с телефона:
по кабелю **Type‑C ↔ Type‑C** (телефон работает как USB-хост) или по Wi‑Fi.
Внутри своя реализация протокола ADB, поэтому ни root, ни бинарник `adb` на телефоне не нужны.

## Возможности

| Вкладка | Что умеет |
|---|---|
| **Шлем** | подключение по USB и Wi‑Fi, поиск шлема в сети, состояние (модель, прошивка, батарея, температура, IP, память), скриншот, кнопки Домой, Назад, громкость, сон/пробуждение, перезагрузка, выключение, **«Включить ADB по Wi‑Fi»** (аналог `adb tcpip 5555`) |
| **Приложения** | список пакетов, установка APK с телефона с прогрессом, запуск VR/2D-приложений, остановка, очистка данных, удаление, logcat конкретного приложения |
| **Настройки** | `debug.oculus.*`: частота 60–120 Гц, уровни CPU/GPU, фовеация, разрешение eye-buffer, пауза Guardian, отключение датчика присутствия, сброс всего |
| **Консоль** | живой logcat с аргументами (`*:W`, `-s Unity`, `--pid=…`), фильтр по тексту, подсветка ошибок и предупреждений, экспорт лога, произвольные `adb shell` команды |

## 1. Установка приложения на телефон

APK собирает GitHub Actions при каждом пуше. Готовые файлы лежат в **Releases** репозитория
(`build-N`), а также в артефактах запуска workflow **Android APK**.

Телефон подключён к компьютеру по ADB:

```bash
adb install -r QuestRemote-N.apk
adb shell am start -n com.prnoia.questremote/.ui.MainActivity
```

Другой вариант: скачать APK прямо на телефон со страницы Releases и открыть его
(понадобится разрешить установку из этого источника).

Все сборки подписаны одним тестовым ключом (`keystore/debug.keystore`), поэтому
новая версия ставится поверх старой без удаления. **Для продакшена этот ключ не годится.**

Собрать локально (нужен Android SDK / Android Studio):

```bash
./gradlew assembleDebug          # APK: app/build/outputs/apk/debug/app-debug.apk
./gradlew installDebug           # сразу на подключённый телефон
./gradlew testDebugUnitTest      # тесты протокола ADB против поддельного adbd
```

## 2. Отладка самого приложения на телефоне

Разъём Type‑C у телефона будет занят шлемом, поэтому отладку телефона переносим на Wi‑Fi,
**пока телефон ещё подключён к ПК кабелем**:

```bash
adb tcpip 5555                       # телефон начинает слушать ADB по сети
adb connect <IP_телефона>:5555       # IP: Настройки → О телефоне → Статус
# теперь кабель от ПК можно отключить и воткнуть шлем
adb -s <IP_телефона>:5555 logcat --pid=$(adb -s <IP_телефона>:5555 shell pidof -s com.prnoia.questremote)
```

На Android 11+ можно без кабеля: *Для разработчиков → Отладка по Wi‑Fi → Подключить с кодом*,
затем `adb pair <ip>:<port>` и `adb connect <ip>:<port>`.

Всё, что приложение делает со шлемом, дублируется во вкладке **Консоль**.
Её можно выгрузить кнопкой **Экспорт**.

## 3. Подготовка Quest 2 (один раз)

1. В приложении **Meta Horizon** на телефоне: *Устройства → Настройки гарнитуры → Режим разработчика → Вкл*
   (нужна учётная запись разработчика Meta, бесплатная).
2. Перезагрузите шлем.

## 4. Подключение по кабелю Type‑C ↔ Type‑C

1. Воткните кабель в телефон и в шлем. Кабель должен передавать данные, а не только заряжать.
2. Android предложит открыть **Quest Remote** для этого устройства. Можно поставить «Всегда».
   Если окно не появилось, откройте приложение и нажмите **Подключить по USB**.
3. Наденьте шлем и в диалоге **«Разрешить отладку по USB?»** нажмите *Разрешить*.
   Лучше с галочкой «Всегда разрешать», тогда при следующих подключениях вопроса не будет.

**Если шлем не находится.** У кабеля C‑C роли хост/устройство согласуются автоматически,
и иногда хостом становится шлем. Что можно сделать:

- в шторке телефона нажмите на уведомление USB → **«USB управляет: это устройство»**;
- переподключите кабель другим концом (или переверните штекер);
- используйте OTG-переходник на стороне телефона. Он принудительно делает телефон хостом.

## 5. Переход на Wi‑Fi

Подключившись по кабелю, нажмите **«Включить ADB по Wi‑Fi»**. Приложение само подставит IP шлема.
Через пару секунд нажмите **«По Wi‑Fi»**, и кабель можно отключить.
Режим сбрасывается после перезагрузки шлема. Без кабеля его можно включить с ПК: `adb tcpip 5555`.

## Как это устроено

```
app/src/main/java/com/prnoia/questremote/
├── adb/
│   ├── AdbConnection.kt   протокол ADB: CNXN/AUTH/OPEN/OKAY/WRTE/CLSE, потоки, flow control
│   ├── AdbCrypto.kt       RSA-ключ телефона, подпись токена, формат публичного ключа adbd
│   ├── AdbTransport.kt    интерфейс транспорта + TCP (Wi‑Fi)
│   ├── UsbTransport.kt    USB Host API: bulk-эндпоинты ADB-интерфейса (0xFF/0x42/0x01)
│   ├── UsbAdb.kt          поиск устройств и запрос USB-разрешения
│   ├── NetworkScanner.kt  поиск открытого порта 5555 в подсети /24
│   └── QuestController.kt состояние подключения, shell, установка APK, скриншот, logcat
└── ui/                    MainActivity и вкладки: Device, Apps, Tweaks, Console
```

- Установка APK: `exec:cmd package install -S <размер>` с потоковой передачей файла.
- Скриншот: `exec:screencap -p`.
- Перезагрузка и `tcpip`: служебные сервисы adbd `reboot:` и `tcpip:5555`.
- Ключ телефона хранится в приватной папке приложения. После переустановки
  с очисткой данных шлем спросит разрешение заново.

## Ограничения и идеи на потом

- Трансляции экрана шлема на телефон (как scrcpy) пока нет, есть только скриншоты.
- Параметры `debug.oculus.*` действуют до перезагрузки и применяются при следующем запуске VR-приложения.
- Уровень заряда контроллеров не показывается: у Meta нет стабильного публичного способа его получить.
